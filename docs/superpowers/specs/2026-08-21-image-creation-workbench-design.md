# EnovaMotion 图片创作工作台重构设计

## 背景

当前 `/app/images` 已具备文生图、单图编辑、多图合成、任务轮询、结果预览和 Credits 展示，但页面仍带有后台管理系统的信息架构特征。普通创作者会在侧栏看到与创作无关的管理入口，历史任务与当前创作也被拆成独立页面，难以形成连续创作体验。

本次重构参考即梦的空间结构、ChatGPT 的历史会话入口和 Midjourney 的结果画廊，目标是把图片生成页改造成聚焦内容的 AI 创作工作台。参考产品只用于指导布局和交互，不复制其品牌、颜色或受保护素材。

## 已确认范围

- 仅修改 `apps/web` 的布局、导航、图片创作会话投影、结果画布和 Prompt Composer。
- 保留现有图片生成 API、上传流程、任务状态轮询、Credits 估算和错误处理。
- 不新增数据库表、API 或真实 `GenerationConversation` 领域模型。
- 不修改 Provider、计费、Worker、对象存储或生成任务状态机。
- 图片“会话”由前端把现有生成任务历史投影为创作入口；每条任务仍是唯一持久化事实。
- 视频创作页复用新的普通用户工作台导航，但本次不改造成图片式会话界面。
- 管理页面继续位于现有 `/app/admin/*`，只允许管理员访问，且不出现在普通用户创作导航中。

## 视觉与交互原则

### 视觉主张

浅灰画布承托白色创作内容，以大面积留白、克制边框和弱阴影形成安静、聚焦的 AI 创作工作台；品牌和生成结果是视觉锚点，导航退居辅助层。

### 内容结构

1. 固定窄导航：Logo、灵感、生成、资产、画布，以及底部账户/Credits。
2. 可展开会话入口：默认收起，打开后以浮层展示新对话、默认创作和最近任务。
3. 中央生成画布：标题、prompt 元信息、任务状态和结果网格。
4. 固定底部 Prompt Composer：参考图、输入、模式、模型、比例、分辨率、Credits 和生成按钮。

### 交互主张

- 会话浮层采用短距离滑入和淡入，不改变中央画布宽度。
- 图片 hover 时显露操作条，离开后恢复干净的画廊展示。
- 生成中沿用现有 shimmer 和轮询状态，并让新任务即时出现在最近列表中。

## 信息架构

### 普通用户工作台

普通用户侧栏收敛为一级导航：

- 灵感：本期作为入口占位，不虚构未实现业务。
- 生成：进入 `/app/images`；视频能力通过生成入口中的已有路由继续可达。
- 资产：链接现有生成历史/资产能力。
- 画布：本期作为入口占位，不虚构未实现业务。

管理员菜单、Provider、定价、审计、系统设置和系统更新不显示在普通创作侧栏。管理员访问 `/app/admin/*` 时沿用受权限保护的后台导航与页面结构。

### 图片会话浮层

会话浮层默认关闭，通过页面左上方的当前会话按钮打开。浮层包含：

- 新对话：清除选中任务和当前输入，回到空白创作状态。
- 默认创作：与新对话一致，作为稳定的起始入口。
- 最近：使用现有 `Generation` 列表按时间倒序展示。

最近项使用 prompt 首行生成标题；空 prompt 使用本地化的兜底标题。成功任务显示结果缩略图，运行中/失败任务显示对应状态图标。当前任务保持高亮。

## 图片创作数据流

1. 页面加载后继续通过现有 `generationApi.list(50)` 获取任务历史。
2. 任务通过既有 `toImageTask` 规范化，不增加服务端字段。
3. 最近列表直接消费 `ImageTask[]`，不在 `localStorage` 保存额外会话关系。
4. 点击任务时更新 `selectedTaskId`，并调用现有表单回填逻辑加载 prompt、模式、模型、比例、分辨率和参考图。
5. 提交生成时继续创建乐观任务；任务立即显示在画布和最近列表中。
6. API 返回真实任务后替换乐观任务；轮询继续更新状态，成功后显示结果，失败后显示既有错误反馈。

该数据流不把多个任务声明为一个真实持久化 conversation。用户感知到的“继续创作”来自参数回填、编辑和再次生成。

## 中央画布

### 空状态

- 保留现有创作模板数据与选择行为。
- 降低页面标题和说明的后台页面感，改为以创作提示和灵感模板为主。
- 中央保留足够留白，Prompt Composer 始终可见。

### 任务状态

- 顶部显示由 prompt 派生的标题。
- 元信息行显示完整 prompt、用户可见模型名、比例、分辨率和格式化生成时间。
- 运行中继续显示四格 shimmer 与状态文字。
- 失败或取消继续显示错误状态和重新生成操作。

### 结果区

- 使用可扩展的响应式网格：当前 API 只有单个 `output.url` 时显示单图，多任务/未来多结果时自然扩展为横向多图。
- 图片 hover 操作包括下载、重新生成、编辑、收藏和更多；仅对已有回调开放可用操作，未持久化的收藏不得伪装为跨会话保存。
- 卡片边框弱化，图片本身成为主视觉。

## Prompt Composer

Prompt Composer 固定在页面底部，并保持与中央内容对齐：

- 上层为多行文本输入，Enter 提交，Shift+Enter 换行。
- 参考图在输入区内部上方展示，支持替换和删除。
- 左侧提供上传参考图和字符计数。
- 中部提供文生图、单图编辑、多图合成模式。
- 右侧提供模型、比例、分辨率、预计 Credits、余额和圆形生成按钮。
- 生成期间禁用可变参数并显示上传/生成状态。
- 校验和服务端错误继续在 Composer 内展示。

## 响应式行为

- 桌面：窄导航常驻，会话列表以浮层展开，画布宽度不变。
- 平板：会话列表使用覆盖式抽屉，点击遮罩或选择任务后关闭。
- 移动：导航进一步收窄或使用现有移动开关；Composer 工具栏换行，结果网格为一至两列，所有按钮保留可触达尺寸。
- 固定 Composer 必须给滚动画布预留底部空间，避免遮挡最后一行结果。

## 组件边界

- `AppShell`：根据普通用户路由和管理员路由呈现不同导航结构；不持有图片任务状态。
- `ImageView`：继续拥有表单、上传、历史、选中任务、乐观更新和轮询状态。
- 图片会话组件：只渲染任务投影并发出“新对话/选择任务/关闭”事件。
- 生成头部与元信息组件：只根据当前任务渲染标题和参数。
- `GenerationCanvas` / `ImageGrid` / `ImageCard`：负责状态和结果展示，复用现有操作回调。
- `PromptComposer`：负责输入与参数控件，不直接调用 API。

## 错误与边界状态

- 历史加载为空时显示默认创作，不展示空白会话浮层。
- 任务缺少 prompt、模型、比例、尺寸或时间时使用安全兜底，不中断渲染。
- 缩略图加载失败时退回状态图标。
- 任务生成失败、取消、上传失败、余额/API Key 不足继续走现有提示和对话框。
- 本地隐藏历史任务保持当前语义，不暗示服务端已删除。

## 测试与验收

至少验证：

- 会话标题派生和缺失字段兜底。
- 打开/关闭会话浮层、新对话、选择历史任务和参数回填。
- 成功、生成中、失败和空状态的画布展示。
- Prompt Composer 的模式切换、上传入口、Enter/Shift+Enter 和提交禁用条件。
- 管理入口不会出现在普通创作导航；管理员路由仍受既有权限保护。
- 桌面、平板和移动宽度下无内容遮挡或不可触达控件。

工程验证依次运行 `apps/web` 的 lint、typecheck 和相关 Vitest 测试；如环境允许，再运行 web build 或根目录相关校验。

## 非目标

- 不实现真实连续会话持久化、会话重命名、跨设备同步或会话删除。
- 不新增多结果生成能力；只为现有/未来结果数量提供兼容布局。
- 不实现灵感、画布、收藏的服务端业务。
- 不修改管理员业务页面、权限模型、数据库 migration、OpenAPI 或生成 SDK。
